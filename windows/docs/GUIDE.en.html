1. First steps

Zetalvx Image Lab — Qwen 2.1 Edition generates, edits and combines images with Qwen Image 2.1. This Linux revision retains components, presets, model profiles and Decode Lab.

  1. Set up the first account; on another device, enter the temporary pairing code displayed on the host.
  2. In Models → My models, link the complete Qwen repository or the repository plus a compatible transformer override.
  3. Save and check the components. Ready means the file check passed, not that generation was tested.
  4. Create or open a project. In Create / Edit, enter a prompt and run a first test, for example at 1024 × 1024.

Paths refer to the host computer, not the phone. Model weights are not bundled.

2. Navigation and mobile menu

The bottom bar has Home, Create / Edit, Library and More, evenly filling its width. More contains Models, Tools, Presets, Projects, Jobs, Guide and Settings. More stays highlighted while you are on a secondary page.

Close More with Close, the backdrop or Escape. Tab stays within the open panel. Models tabs also support arrow keys, Home and End.

On an image card, Add input adds the image to the ordered Qwen inputs. Reuse settings restores that result’s prompt and generation settings in Create / Edit so you can adjust them and start a new job yourself. Neither action starts generation. More actions contains Details, Edit / tools, Save PNG and Delete.

The guide has a compact fifteen-topic navigator and a single article reader. Search in your language, select a topic and use Previous, Next or All topics without a second repeated list.

Tapping an image enlarges it; it does not create an implicit active-image selection.

3. Generation and editing

There is one workspace: no attachments generates from text; one attachment edits or uses an image as a reference; several attachments combine ordered references. State what should change and what should remain. Attachments are next to the prompt; queue and history follow the form directly, without a duplicate preview.

Seed -1 chooses a random value; zero is valid. Initial settings remain 40 steps with True CFG off. Advanced settings expose dimensions, batch, CFG/negative prompt, per-job transformer and decode options.

Each queued job keeps its own settings. Batch creates separate jobs; refreshing the page does not cancel server-side work. Use Cancel for an active job. Reuse settings fills the form; generation starts only when you submit it.

For repeatable comparisons, keep prompt, seed, dimensions, components, precision and decode settings. Changing the seed is not an isolated decoder comparison.

Prompt Enhancer

Uses an existing local ComfyUI environment in a separate process. No server, installation or model download. Its process exits before image generation.

Existing ComfyUI folder + Python from that ComfyUI environment. Review the runtime paths and confirm trust.

4. Attachments and transparent PNG

Attach up to 10 images next to the prompt, from your device or Library. The displayed order is passed to Qwen: refer to “Image 1”, “Image 2” in the prompt. Arrows reorder inputs; removing an attachment does not delete its Library file. Inputs belong to the project.

Request transparent PNG (RGBA) requests transparency and preserves the actual returned alpha. The checkerboard reveals transparent areas; a painted dark background is not transparency. An opaque result is reported; no hidden external cutout model runs.

On an image card, Add input adds the image to the ordered Qwen inputs. Reuse settings restores that result’s prompt and generation settings in Create / Edit so you can adjust them and start a new job yourself. Neither action starts generation. 5. Repository, transformer and catalog

Diffusers means the component-structured repository; GGUF and safetensors can override the transformer. A GGUF file alone is not the full model: configuration, processor/tokenizer, text encoder, scheduler and compatible VAE are still needed.

Set the main directory and optional override under My models. Checks show a compact summary; expand Files and compatibility details for paths. Missing-file details are expanded on their first display.

Everything linked, uploaded or downloaded appears here and in the selectors above. Choose a component already linked, uploaded or downloaded. The selected path is shown below. Component selected in the form. Save the configuration or save it as a model profile.

Before saving, check which transformer the next job will use: the Create / Edit per-job override can take precedence over model configuration.

6. VAE, decoder and other components

Select a compatible component from Available components or keep the base repository default. Choose a component already linked, uploaded or downloaded. The selected path is shown below.

The decoder is part of the VAE; arbitrary layer mixing is not supported. Prefer a complete Diffusers VAE folder; a single file requires matching native keys and configuration. A ComfyUI conversion is not automatically equivalent.

The 64 × 64 CPU VAE test checks strict weights, dimensions and finite values in an RGBA round-trip. It does not certify image quality or 2048 memory use. Reset to official edits the form; save to apply it.

Texture-Fix is an optional source to review, not bundled content. Its button opens the source in the download flow: review the weight terms. Static scheduler shift disables dynamic shifting; leave it empty to retain the sampler.

Encoder weights

INT8 ConvRot uses an optional floating-point reconstruction path, not native INT8 kernels. It is not a native INT8 speed or VRAM benchmark.

Native ConvRot: for supported single-file Qwen 2.1 Transformer/Text Encoder safetensors, Benchmark Lab can use the existing verified ComfyUI runtime without Image Lab float reconstruction. Native T2I requires explicit single-file Transformer, Text Encoder and VAE. Unsupported combinations fail only that job and the remaining batch continues. Reference float reconstruction remains a separate quality/debug mode; do not use its time or VRAM as native INT8 performance.

7. Model profiles and LoRA

A model profile stores components, transformer, precision, memory, decode settings and LoRA stack. It does not copy weights. Save, Activate, Duplicate, Import/Export and Delete are separate; saving does not activate a profile. Activation requires confirmation.

Already queued jobs are not reconfigured. Review local paths before sharing profile JSON; account tokens are not part of the profile.

LoRAs must be explicitly compatible with Qwen Image 2.1. Set stack order and weights for up to four adapters. Runtime capability is checked. LoRA with GGUF is not enabled and is not silently ignored.

Prompt presets remain separate: profiles choose components/resources, while presets recall creative work.

9. Decode Lab, latents and OOM

With Retain latent on, the exact tensor destined for the VAE is saved before decoding. Sampling finishes, unnecessary models are released and the VAE decodes separately. The next generation may need to reload those models.

If GPU decode runs out of memory after the steps, open Decode Lab below the results. Select a retained latent, CPU and Full frame, then decode. This uses zero sampling steps, but needs RAM and may be slow. It does not guarantee 2048 success on every host.

Auto and Full frame never switch automatically to Tiled or CPU. Tiled and Custom tiles are manual experiments and may reintroduce lines/artifacts. Overlap = tile size − stride.

Compare official and custom VAEs on the same latent. Latents are kept as durable experiment data with no application count or size quota; available disk space is the practical limit. Decode Lab shows archive use and free disk space. Delete entries only when you no longer need exact VAE re-decodes; PNG images remain.

Benchmark Lab

Controlled comparisons, one GPU job at a time.

Uses the prompt, ordered input images, seed, resolution, steps and guidance in Create / Edit. A random seed is resolved once for the whole comparison.

Confirm and queue all tests

Uses the selected output resolution. Deterministic VAE encoding, RGBA8 between cycles; no diffusion. Metrics compare with the resized original.

Timing includes component loading. Sampling, offload and decode are recorded separately when available. Memory values cover this worker, not the entire GPU or system.

Same seed does not guarantee identical outputs across different implementations. Quality and identity preservation must also be inspected visually.

Comparison Gallery: all saved benchmark images can be reopened across projects, grouped by prompt/example, filtered by component and settings, and compared side by side or with an A/B slider. Benchmark reports can be renamed or deleted; full deletion also removes their generated images, jobs, metrics and linked latents.

10. Library, projects and queue

Each project owns its images and jobs. The Library selector and Projects cards switch the active project. Model settings are shared by the installation.

Cards show a title, display number, date/seed when available and a short ID to distinguish assets. The number follows project order and can change after deletion; the ID is the asset identity. The new layout does not rename files.

More actions → Details shows original parameters. Project Trash allows restore; Delete forever removes project data including latents. Save outputs you need before permanent deletion.

Jobs shows phase/progress. Cancel affects one job; clearing queued jobs does not interrupt an already running one.

11. Image tools and FFmpeg

Tools retains image resize, conversion, crop, rotation and flip. Select one or several assets, review parameters and run the operation. New results are saved to the project.

Video · frames uploads a video and selects the first/last frame or a timestamp. Review the FFmpeg preview. The saved PNG comes from the server preview, not a screenshot of the browser player.

Browser playback depends on format; when unsupported, try timestamp selection. Wait for the preview before saving. Switching project discards the previous video selection. This page extracts frames; it does not generate Qwen videos.

12. Downloads and Hugging Face / Civitai accounts

Models contains Add, Downloads and Accounts. For a remote source: paste its link, choose a component type, Inspect, review source/terms/size, then confirm download. Texture-Fix only prepares a source.

Browser upload accepts single weight files only. Full repositories, text encoders, processors and schedulers are folders: link them from the server or download them from Hugging Face. Everything linked, uploaded or downloaded appears here and in the selectors above.

Confirmed downloads run on the server; uploads from your device need the page to remain open. Do not update or uninstall during active transfers.

Accounts use HF/Civitai tokens, not platform passwords. Tokens are stored on the server, not in presets. Removing a token from the app does not revoke it on the platform. Do not share secrets or reports containing private data.

Apache-2.0 covers application code. Weights, LoRA and VAE have their own terms to review at the source, including possible commercial-use restrictions. Downloading them separately does not remove those obligations. Catalog registration does not certify usage rights.

13. Access, network and settings

The Linux home remains ~/.local/share/ImageLabQwen21. Local listens on 127.0.0.1; LAN allows other devices on the network. The default port is 8298. Do not run another app on the same port or expose this service directly to the Internet.

HTTPS remains on. Remote first-account setup needs the temporary code displayed on the host, valid for 20 minutes. Get a new one with imagelab-qwen setup-code. It is not password recovery for an existing account.

Settings manages account, network and Desktop shortcut. Save a network change, then restart to apply. Interface colors are browser-local and do not modify images.

14. Updates, start and uninstall

To update 1.0.27 to 1.0.28: finish jobs/transfers, open Settings → Updates, import the complete Linux ZIP and confirm source/password. Do not unpack/repack the updater ZIP. The process continues on the host; do not start another installer. Check for 1.0.28 after restart.

This polish does not change dependencies. Validated runtimes can be reused; installer checks still run. Rollback returns to the previous version while keeping data.

Commands: imagelab-qwen start, imagelab-qwen stop, imagelab-qwen status, imagelab-qwen setup-code. For a headless host: imagelab-qwen start --lan --no-browser. When absent from PATH, use ~/.local/share/ImageLabQwen21/bin/imagelab-qwen.

Uninstall keeps data unless full removal is explicitly selected. Full removal also deletes internal models/data; back up first. Linked external paths are not deleted. Legacy technical identifiers in the ZIP preserve updater compatibility: do not rename them manually.

15. Diagnostics and common problems

OOM after sampling: check that the latent was retained, then explicitly try full-frame CPU decode. Do not silently substitute Tiled to hide an error; it may produce artifacts. Peak memory depends on dimensions and components, not just weight size.

Purple lines: use Auto/Full frame and compare VAEs on the same latent; a replacement VAE alone does not guarantee a fix.

Ready model but failed generation: inspect Jobs → Details and Models runtime diagnostics. File checks do not prove successful runtime/GPU execution.

Old interface: reload after restart and check the header version. Guide search only searches guide text, not prompts or images.

Logs are under shared/logs; installer reports are under shared/audits inside the Qwen home. Share the relevant error/settings, not tokens, passwords or the entire private directory.

16. Automated Benchmark Lab

Benchmark Lab runs controlled batches through the same serial GPU queue used by normal generation. Choose a suite, one baseline model preset, then select the registered Transformer, encoder or VAE components to compare.

Transformer quality and Encoder instruction-following include ready test prompts and default to 1024 × 1024, 30 steps and seed 314159. The matrix combines selected Transformers and encoders. VAE comparison can decode the same preserved latent or run deterministic 1×/5×/10× round-trips.

Nothing starts until Prepare batch creates a reviewable plan and you confirm it. Results record total, loading, sampling and decode time, peak CUDA allocated/reserved memory, peak process RAM, selected components and output images. Export JSON or CSV for later analysis.

Components come from Models; the benchmark does not guess files from the filesystem. Add or link a component there once, then select it in the batch.
