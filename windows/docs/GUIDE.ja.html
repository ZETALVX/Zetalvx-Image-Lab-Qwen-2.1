1. はじめに

Zetalvx Image Lab — Qwen 2.1 Edition は Qwen Image 2.1 で画像を生成、編集、合成します。この Linux 版はコンポーネント、プリセット、モデルプロファイル、Decode Lab を維持しています。

  1. 最初のアカウントを作成します。別の端末からは、サーバーに表示された一時コードを入力します。
  2. モデル → マイモデルで完全な Qwen リポジトリ、またはリポジトリと互換性のある代替 Transformer を指定します。
  3. 保存してコンポーネントを確認します。準備完了はファイルの確認成功であり、生成テストの成功を意味しません。
  4. プロジェクトを作成または開き、作成 / 編集で指示を入力し、必要に応じて画像を添付します。最初は 1024 × 1024 などで試してください。

パスは電話ではなくサーバー上の場所です。モデルの重みは配布パッケージに含まれません。

2. 操作とモバイルメニュー

下部バーのホーム、作成 / 編集、ライブラリ、その他は幅いっぱいに均等に配置されます。その他にはモデル、ツール、プリセット、プロジェクト、ジョブ、ガイド、設定があり、これらのページではその他が選択表示されます。

閉じるボタン、パネル外のタップ、Esc で閉じます。Tab は開いたパネル内を移動します。モデルのタブは矢印、Home、End キーにも対応します。

画像カードの入力に追加は画像を順序付き Qwen 入力に追加します。設定を再利用はその結果のプロンプトと生成設定を作成/編集画面に復元し、調整して自分で新しいジョブを開始できます。どちらも生成を開始しません。その他の操作には詳細、編集 / ツール、PNG 保存、削除があります。

ガイドには15項目のコンパクトな目次と単一の記事欄があります。選択言語で検索し、項目を開き、前へ、次へ、すべての項目で移動できます。項目一覧は重複しません。

3. 生成と編集

作業画面は共通です。添付なしならテキストから生成し、1枚なら編集または参照、複数なら順序付きの参照画像を合成します。変更する内容と維持する内容を明示してください。添付欄は指示の近くにあり、フォームの下はキューと履歴です。重複プレビューはありません。

シード -1 はランダム値です。0 も有効です。初期設定は40ステップ、True CFG はオフです。詳細設定にはサイズ、バッチ、CFGとネガティブ指示、ジョブ別 Transformer、デコードの設定があります。

キューに入れたジョブはその時点の設定を保持します。バッチは個別ジョブを作成します。ページ更新ではサーバーの処理は中止されません。実行中のジョブはキャンセルを使います。設定再利用はフォームに値を戻すだけで、送信するまで生成しません。

再現性のある比較では指示、シード、サイズ、コンポーネント、精度、デコード設定を揃えてください。シードを変えるとデコーダーだけの比較にはなりません。

プロンプト改善

生成前に任意でプロンプトを改善します。自動実行はしません。

既存のローカルComfyUIを別プロセスで使用します。サーバー起動、インストール、モデルのダウンロードはしません。画像生成前に終了します。

PEファイルを追加 → PE-I2I · 入力画像 / PE-T2I · テキストのみ.

既存ComfyUIフォルダー + そのComfyUI環境のPython. 環境のパスを確認し、信頼を承認してください。

改善したプロンプトをプレビュー → 改善したプロンプト · 編集可能 → このプロンプトを使用. プロンプトだけを置き換えます。画像、シード、サイズ、生成設定は変わりません。

512トークンから開始。トークン数や思考を増やすと時間とメモリを多く使う場合があります。

Image Labの既定指示は独自の簡潔なものです。Qwen公式system_prompt.txtのコピーではありません。試したい指示はカスタム欄に貼り付けてください。

4. 添付画像と透明 PNG

指示の近くで、端末またはライブラリから最大10枚を添付できます。表示順が Qwen に渡る順です。指示内では “Image 1”、“Image 2” と指定してください。矢印で並べ替え、添付から外してもライブラリのファイルは削除されません。入力はプロジェクトに属します。

透明 PNG を要求（RGBA）は透明背景を要求し、実際に返されたアルファを保持します。市松模様は透明部分を示しますが、描画された暗い背景は透明ではありません。不透明な結果は通知され、外部の背景除去モデルを隠れて実行することはありません。

画像カードの入力に追加は画像を順序付き Qwen 入力に追加します。設定を再利用はその結果のプロンプトと生成設定を作成/編集画面に復元し、調整して自分で新しいジョブを開始できます。どちらも生成を開始しません。その他の操作には詳細、編集 / ツール、PNG 保存、削除があります。

5. リポジトリと Transformer

Diffusersはコンポーネント構成のリポジトリです。GGUFや safetensors は Transformer の代替に使えます。GGUF だけでは完全なモデルになりません。設定、processor/tokenizer、テキストエンコーダー、スケジューラー、互換 VAE が必要です。

マイモデルで主フォルダーと必要な代替ファイルを設定します。確認結果は簡潔な概要となり、ファイルと互換性の詳細を開くとパスを確認できます。不足ファイルの詳細は最初の表示で展開されます。

リンク、アップロード、ダウンロードしたものはすべて、ここおよび上の選択欄に表示されます。 リンク、アップロード、またはダウンロード済みのコンポーネントを選択します。選択したパスは下に表示されます。 フォームでコンポーネントを選択しました。設定を保存するか、モデルプロファイルとして保存してください。

保存前に次のジョブの Transformer を確認してください。作成 / 編集のジョブ別指定がモデル全体の設定に優先する場合があります。

6. VAE とその他のコンポーネント

「利用可能なコンポーネント」から互換コンポーネントを選ぶか、ベースリポジトリの既定値を使用します。 リンク、アップロード、またはダウンロード済みのコンポーネントを選択します。選択したパスは下に表示されます。

デコーダーは VAE の一部であり、任意の層の混在には対応しません。完全な Diffusers VAE フォルダーを推奨します。単一ファイルには一致するネイティブキーと設定が必要です。ComfyUI 変換版は自動的に同等とは見なしません。

64 × 64 の CPU VAE テストは、重みの厳密な一致、サイズ、RGBA のエンコード・デコードでの有限値を確認します。画質や 2048 のメモリ使用量は保証しません。公式に戻す操作はフォームを変更するだけです。保存して適用します。

Texture-Fix は確認が必要な任意の提供元であり、同梱しません。ボタンはダウンロード手順を開きます。重みの利用条件を確認してください。静的シフトは動的シフトを無効にします。空欄なら元のサンプラーを維持します。

エンコーダーの重み

INT8 ConvRotは任意の浮動小数点復元を使用し、ネイティブINT8カーネルではありません。ネイティブINT8の速度・VRAMのベンチマークではありません。

ネイティブ ConvRot: 対応する Qwen 2.1 Transformer/Text Encoder の single-file safetensors は、Image Lab の float 復元を行わず、既存の確認済み ComfyUI ランタイムで Benchmark Lab から実行できます。ネイティブ T2I には明示的な single-file Transformer、Text Encoder、VAE が必要です。未対応の組み合わせはそのジョブだけ失敗し、残りのバッチは続行します。float 復元は品質/デバッグ用の別モードであり、その時間や VRAM はネイティブ INT8 性能ではありません。

7. モデルプロファイルと LoRA

モデルプロファイルはコンポーネント、Transformer、精度、メモリ、デコード設定、LoRA スタックを保存します。重みはコピーしません。保存、有効化、複製、インポート/エクスポート、削除は別操作です。保存だけでは有効になりません。有効化には確認が必要です。

キュー内のジョブは再設定されません。JSON を共有する前にローカルパスを確認してください。アカウントのトークンはプロファイルに含みません。

LoRA は Qwen Image 2.1 との明示的な互換性が必要です。最大4個の順序と強度を設定できます。実行環境の機能を確認します。GGUF と LoRA の併用は無効であり、黙って無視することはありません。

指示のプリセットとは別です。プロファイルはコンポーネントと資源を選択し、プリセットは創作設定を呼び出します。

9. Decode Lab とメモリ不足

潜在テンソルを保持を有効にすると、VAE に渡す正確なテンソルをデコード前に保存します。サンプリングが終了し、不要なモデルを解放して VAE が別にデコードします。次の生成ではモデルの再読み込みが必要な場合があります。

ステップ完了後に GPU メモリ不足になったら、結果の下の Decode Lab を開きます。保存済みテンソル、CPU、フルフレームを選んでデコードします。サンプリングは0ステップですが、RAM が必要で時間がかかる場合があります。すべての環境で 2048 の成功を保証するものではありません。

自動とフルフレームは勝手にタイルや CPU に切り替わりません。標準/カスタムタイルは手動実験用で、線やアーティファクトが再発する可能性があります。重なり幅 = タイルサイズ − ストライドです。

同じ latent で公式 VAE とカスタム VAE を比較できます。latent は永続的な実験データとして保存され、アプリによる件数・合計容量の上限はありません。実際の上限はディスクの空き容量です。Decode Lab には使用量と空き容量が表示されます。同じ VAE decode を再現する必要がなくなった場合にだけ削除してください。PNG 画像は残ります。

ベンチマークラボ

条件を揃えて比較し、GPUジョブを1つずつ実行します。

「作成／編集」のプロンプト、画像の順序、シード、解像度、ステップ、ガイダンスを使用。ランダムシードは比較全体で1回だけ決定します。

確定して全テストをキューへ

選択した出力解像度を使用。決定的なVAEエンコードで、各サイクル間はRGBA8、拡散処理なし。指標はリサイズした元画像との比較です。

時間には読み込みを含みます。可能な場合はサンプリング、オフロード、デコードを別記録。メモリ値はこのプロセスのみでGPU全体やシステム全体ではありません。

同じシードでも実装が異なると同一出力は保証されません。画質と人物の同一性も目視で確認してください。

10. ライブラリ、プロジェクト、キュー

各プロジェクトは独自の画像とジョブを持ちます。ライブラリの選択欄とプロジェクトカードで現在のプロジェクトを切り替えます。モデル設定はインストール全体で共有されます。

カードはタイトル、表示番号、利用可能な日付/シード、短い IDを表示します。番号はプロジェクトの順で、削除後に変わる場合があります。ID が資源の識別子です。新しい表示はファイル名を変更しません。

その他の操作 → 詳細で元のパラメーターを確認できます。プロジェクトのゴミ箱から復元でき、完全削除は潜在テンソルを含むデータを削除します。必要な結果を先に保存してください。

ジョブは段階と進捗を表示します。キャンセルは1件が対象で、待機キューのクリアは実行中のジョブを中断しません。

11. 画像ツールと FFmpeg

ツールにはサイズ変更、形式変換、切り抜き、回転、反転が残っています。1件以上を選び、パラメーターを確認して実行します。新しい結果はプロジェクトに保存されます。

動画 · フレームでは動画をアップロードし、先頭/末尾フレームまたは時刻を指定します。FFmpeg プレビューを確認してください。保存 PNG はサーバープレビュー由来で、ブラウザープレイヤーのスクリーンショットではありません。

再生は形式に依存します。再生できない場合は時刻指定を試してください。プレビューを待ってから保存します。プロジェクトを変えると前の動画選択を解除します。このページはフレーム抽出用で、Qwen 動画は生成しません。

12. ダウンロードと HF / Civitai

モデルには追加、ダウンロード、アカウントがあります。外部提供元の場合はリンクを貼り、種類を選び、調査して提供元、条件、サイズを確認した後にダウンロードを承認します。Texture-Fix は提供元を入力するだけです。

ブラウザアップロードは単一の重みファイルのみ対応します。完全なリポジトリ、Text Encoder、Processor、Scheduler はフォルダなので、サーバーからリンクするか Hugging Face からダウンロードしてください。 リンク、アップロード、ダウンロードしたものはすべて、ここおよび上の選択欄に表示されます。

承認済みダウンロードはサーバーで続きます。端末からのアップロードではページを開いておく必要があります。転送中は更新やアンインストールを行わないでください。

アカウントにはプラットフォームのパスワードではなく HF/Civitai トークンを使います。トークンはサーバーに保存され、プリセットには入りません。アプリから削除しても提供元では失効しません。secrets や個人情報を含むレポートを共有しないでください。

Apache-2.0 はアプリのコードを対象とします。重み、LoRA、VAE は商用制限を含む別の条件を持つ場合があります。別途ダウンロードしても条件は免除されません。カタログ登録は利用権の認証ではありません。

13. アクセス、ネットワーク、設定

Linux の保存先は引き続き ~/.local/share/ImageLabQwen21 です。ローカルは 127.0.0.1、LANは同じネットワークの他端末からアクセスできます。既定ポートは 8298 です。同じポートで他のアプリを実行せず、サービスを直接インターネットへ公開しないでください。

HTTPS は有効です。リモートで最初のアカウントを作るには、サーバーに表示される20分有効のコードが必要です。imagelab-qwen setup-code で再発行できます。既存アカウントのパスワード復旧機能ではありません。

設定でアカウント、ネットワーク、デスクトップショートカットを管理します。ネットワーク変更は保存後に再起動します。配色はブラウザー内だけで、画像を変えません。

14. 更新、起動、アンインストール

1.0.27 から 1.0.28 へは、ジョブと転送を終え、設定 → 更新で Linux ZIP 全体を読み込み、提供元とパスワードを確認します。ZIP を展開・再圧縮しないでください。処理はサーバーで続くため、別のインストーラーは起動しません。再起動後に 1.0.28 を確認します。

今回の調整は依存関係を変更しません。検証済みの環境は再利用できますが、インストーラーの検査は行います。ロールバックではデータを保持して前版に戻ります。

コマンド：imagelab-qwen start、imagelab-qwen stop、imagelab-qwen status、imagelab-qwen setup-code。ブラウザーなし：imagelab-qwen start --lan --no-browser。PATH にない場合：~/.local/share/ImageLabQwen21/bin/imagelab-qwen。

アンインストールは完全削除を明示しない限りデータを保持します。完全削除は内部モデルも削除するため事前にバックアップしてください。外部リンク先は削除しません。ZIP の旧技術名は更新互換性に必要です。手動で改名しないでください。

15. 診断とよくある問題

ステップ後の OOM：テンソル保存を確認し、CPU フルフレームを明示的に試してください。エラーを隠すためにタイルへ変更しないでください。アーティファクトが出る場合があります。ピークメモリは重みだけでなくサイズと構成に依存します。

紫の線：自動/フルフレームを使い、同じテンソルで VAE を比較します。VAE の交換だけで解決する保証はありません。

準備完了なのに生成失敗：ジョブ → 詳細とモデルの実行環境診断を確認します。ファイル確認は実機 GPU の成功を証明しません。

古い画面：再起動後に再読み込みし、ヘッダーのバージョンを確認します。ガイド検索はガイド内だけで、指示や画像は検索しません。

ログは Qwen フォルダー内の shared/logs、インストールレポートは shared/audits にあります。関連するエラーと設定のみ共有し、トークン、パスワード、私有フォルダー全体は共有しないでください。

16. 自動 Benchmark Lab

Benchmark Lab は通常生成と同じ直列 GPU キューで、条件を固定したバッチ比較を実行します。テストスイートと基準モデルプリセットを選び、登録済みの Transformer、エンコーダー、VAE から比較対象を指定します。

Transformer 品質とエンコーダーの指示追従にはテスト用プロンプトが用意され、初期値は 1024 × 1024、30 steps、seed 314159 です。Matrix は選択した Transformer とエンコーダーを組み合わせます。VAE は同じ保存 latent の decode 比較、または決定論的な 1×/5×/10× round-trip を実行できます。

バッチを準備で確認可能な計画を作成し、承認するまで処理は始まりません。結果には総時間、ロード、sampling、decode、CUDA allocated/reserved のピーク、プロセス RAM のピーク、使用コンポーネント、出力画像を記録します。JSON/CSV に書き出せます。

コンポーネントはモデルから取得します。Benchmark がファイルシステムから推測することはありません。一度追加またはリンクし、バッチで選択してください。

ネイティブ ConvRot: 対応する Qwen 2.1 Transformer/Text Encoder の single-file safetensors は、Image Lab の float 復元を行わず、既存の確認済み ComfyUI ランタイムで Benchmark Lab から実行できます。ネイティブ T2I には明示的な single-file Transformer、Text Encoder、VAE が必要です。未対応の組み合わせはそのジョブだけ失敗し、残りのバッチは続行します。float 復元は品質/デバッグ用の別モードであり、その時間や VRAM はネイティブ INT8 性能ではありません。
